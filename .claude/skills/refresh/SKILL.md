## 항목 다시 확인하기
루틴이 매일 한 번 돌리고, 사람이 `/refresh` 로 불러도 같은 절차다. 무인으로 돌 때는 rules 저장소의 `skills/routine/SKILL.md` 가 먼저다 — PR 로만 내고, 같은 루틴의 PR 이 열려 있으면 돌지 않는다. 조사·표기 규칙의 원본은 `CLAUDE.md` 의 `조사할 때` · `갱신할 때` · `무료·유료를 적는 법` 이고 여기에 다시 적지 않는다.

루틴 프롬프트는 이 두 줄이다.
```
/home/user/rules/skills/routine/SKILL.md 를 읽고 따른다.
/home/user/ai-crew-atlas/.claude/skills/refresh/SKILL.md 의 절차를 한 번 돈다.
```

### 1. 고른다 — 한 번에 도구 2개
- 순서는 `확인한 날짜` 가 오래된 도구 → 같으면 `(검색 요약)`·`확인 못 함` 표시가 많은 도구 → 같으면 `TOOLS.md` 에 적힌 순서다. 날짜를 첫 기준으로 두는 이유는 못 채운 칸이 남은 도구가 날마다 다시 뽑혀 제자리를 도는 것을 막으려는 것이다
- 표시는 `## 도구` 절 안의 항목마다 센다. 절을 안 가르면 `### 조합 예` 같은 관계도 절까지 도구로 잡힌다: `awk '/^## /{on=($0=="## 도구")} on&&/^### /{t=$2; c[t]+=0} on&&t&&/검색 요약|확인 못 함/{c[t]++} END{for(k in c) print c[k], k}' TOOLS.md | sort -rn` — 도구 수만큼 줄이 나와야 한다
- 2개인 이유는 PR 이 폰에서 한 번에 읽힐 크기라서다. 10개가 5일에 한 바퀴 돈다
- 호출 상한은 아직 없다. 첫 두 실행의 사용량 줄을 보고 여기에 적는다

### 2. 확인한다
- 다섯 칸(`CLAUDE.md` › 항목에 반드시 들어가는 것)을 공식 출처에 대 본다. 가격표 → 도움말·약관 → 공식 문서 순이다
- 열리는지는 `curl -sS -o /dev/null -w '%{http_code}' <주소>` 로 먼저 본다. 403 에 응답 머리 `cf-mitigated: challenge` 가 있으면 사이트의 봇 차단이다(openai·perplexity, 2026-09-29) — 네트워크 설정으로는 안 풀린다
- **200 이어도 숫자가 본문에 없을 수 있다.** 자바스크립트로 그리는 가격표다. 본문에서 값을 못 찾았으면 안 열린 것과 같이 친다
- **값은 공식 출처로 본 것만 고친다.** 검색 요약·제3자 글만 있으면 값은 두고 PR 본문에 `바뀐 듯함 — <출처>` 로만 적는다. 무인 조사가 공식으로 확인된 값을 짐작으로 덮는 것이 이 절차에서 제일 나쁜 일이다
- `(검색 요약)` 값이 공식과 같으면 표시를 떼고 출처를 공식으로 바꾼다. 다르면 새 값을 쓰고 PR 본문에 `옛 값 → 새 값` 을 적는다
- 공식으로 못 본 칸은 `확인 못 함 — <이유> (<오늘 날짜>)` 로 이유와 날짜를 새로 적는다. 다음 차례가 같은 벽을 다시 두드리는지 알 수 있다
- 다섯 칸을 다 시도했으면 `확인한 날짜` 를 오늘(KST, `TZ=Asia/Seoul date +%F`)로 고친다. 못 본 칸은 제 자리에 날짜 붙은 `확인 못 함` 이 남으므로 항목 날짜가 새로워도 그 칸을 믿게 되지는 않는다

### 3. 고친다
- 값이 바뀌면 그 항목과 `한눈에 보기` 표의 그 줄을 같은 커밋에서 같이 고친다
- 새 도구는 넣지 않는다. 넣는 기준을 따지는 것은 사람 몫이다. 후보를 봤으면 PR 본문 `해야 할 것` 에 한 줄 적는다
- `NEXT.md` 는 고치지 않는다. PR 이 기록이다

### 4. 검증한다
- `cd site && npm ci && npm run build` 를 돌린다. 빌드가 기대하는 개수(관계도 · 도구 · 단추 줄)가 안 맞으면 멈추므로 `TOOLS.md` 모양이 깨진 것을 여기서 잡는다. PR 에는 CI 가 없다 — `pages.yml` 은 main 푸시에만 돈다
- 생성물(`site/atlas.html` · `site/dist/`)은 커밋하지 않는다
- 새로 쓴 한국어 줄이 음슴체인지 본다. 영문·숫자 뒤의 `-다` 를 놓치기 쉽다

### 5. 낸다
- 바뀐 게 있으면 PR 을 연다. 날짜만 바뀌어도 연다 — 날짜가 안 올라가면 다음 차례가 같은 도구를 다시 고른다. 제목은 `[routine:atlas-refresh] <도구1> · <도구2> 다시 확인` 이다
- 본문은 routine 스킬의 리포트 꼴을 따른다. `확인한 것` 에 도구마다 본 칸과 출처 주소(등급 포함)를, 바뀐 값은 `옛 값 → 새 값` 으로 적는다
